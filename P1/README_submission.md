### 모델 파이프라인 개요
```bash

본 프로젝트는 종합해양과학기지 관측 수온 데이터의 이상치를 자동으로 탐지하기 위해 XGBoost 기반 이진 분류 모델과 시계열 후처리를 결합하였다.

1. 데이터 및 피처 구성

2024–2025년 라벨링 데이터를 학습에 활용하고, 2026년 관측 데이터를 예측 대상으로 사용한다. 관측소와 수심층별 특성을 반영하기 위해 수온의 변화량, 이동 통계량, 기울기, 기준값 대비 편차 등 총 150개 피처를 사용한다. station, layer, time, label 등은 모델 입력에서 제외하며, 관측소와 수심층 정보는 후처리 단계에서 활용한다.

2. 모델 학습

XGBoost 이진 분류 모델을 사용하여 각 관측값의 이상 확률을 예측한다. 클래스 불균형을 고려해 학습 데이터의 정상·이상 비율로 scale_pos_weight를 설정한다. 모델의 주요 설정은 n_estimators=1000, learning_rate=0.03, max_depth=6, min_child_weight=5, subsample=0.8, colsample_bytree=0.8이다.

3. 시간 기반 검증

2025년 상반기(H1)를 검증 구간으로 두고, 2024년 전체와 2025년 하반기(H2)를 학습에 사용하는 시간 기반 검증을 수행하였다. 추가로 반대 방향의 검증인 2024년 전체 + 2025년 H1 → 2025년 H2를 수행하여 threshold 전략의 시간적 안정성을 비교하였다.

4. 관측소·수심층별 Threshold

모델이 출력한 이상 확률에 관측소·수심층별 threshold를 적용한다. 현재 G 파이프라인은 I-ORS의 일부 수심층에 안정화된 threshold를 적용하고, S-ORS는 수심층별 threshold를 유지하는 방식이다. Threshold는 별도 설정값으로 관리하여 모델 학습과 후처리 단계를 분리한다.

5. Speckle-only 후처리

Threshold 적용 후 관측소·수심층별 시계열에서 짧게 고립된 이상 예측을 제거한다. 길이 2–11인 이상 예측 구간은 제거하되, 해당 구간에 수온 1차 변화량이 1.7 이상인 spike가 포함된 경우에는 보호한다. 최종 파이프라인에는 Flatline 강제 이상 처리와 Gap Filling을 적용하지 않는다.

6. 최종 예측 및 제출

2026년 Test 데이터에 동일한 150개 피처를 적용하고, XGBoost 이상 확률 → G threshold → Speckle-only 후처리 순서로 최종 라벨을 생성한다. 제출 파일은 station, year, layer, time, label의 5개 컬럼으로 구성한다.

개발 및 검증 기록

초기 threshold는 라벨이 있는 검증 데이터에서 탐색하였다. 이후 Public leaderboard 결과를 확인하며 일부 threshold 조합을 비교한 이력이 있으므로, 해당 과정은 별도의 실험 기록에 명시한다. 최종 제출 파이프라인의 재현 코드와 threshold 설정은 별도로 보존한다.
```




## 주요 결정과 근거

### 1. 관측소·수심층별 특성을 고려한 모델링

종합해양과학기지 수온 데이터는 관측소와 수심층에 따라 수온 변화 양상과 이상치 발생 특성이 다르다. 이에 따라 관측소·수심층별 성능을 확인하고, 동일한 확률 임계값을 모든 데이터에 적용하는 방식과 개별 임계값을 적용하는 방식을 비교하였다.

### 2. XGBoost 및 150개 피처 사용

수온의 변화량, 이동 통계량, 기울기, 기준값 대비 편차 등 시계열 특성을 반영한 150개 피처를 사용하였다. XGBoost 이진 분류 모델로 이상 확률을 예측하였으며, 클래스 불균형을 고려해 학습 데이터의 정상·이상 비율로 `scale_pos_weight`를 설정하였다.

### 3. 시간 기반 검증 구간 설정

2026년 상반기 예측 상황을 고려하여, 2024년 전체와 2025년 하반기를 학습하고 2025년 상반기를 검증하는 방식을 사용하였다. 이후 반대 방향인 `2024년 전체 + 2025년 상반기 → 2025년 하반기` 검증을 추가하여 threshold 전략의 시간적 안정성을 확인하였다.

### 4. 관측소·수심층별 Threshold 적용

초기에는 검증 데이터의 F1을 기준으로 관측소·수심층별 threshold를 탐색하였다. 전체 공통 threshold보다 개별 threshold 방식의 검증 성능이 높아 이를 기본 전략으로 채택하였다. 다만 일부 수심층에서는 검증 기간에 따라 최적 threshold가 크게 달라져 과적합 가능성을 확인하였다.

### 5. Speckle-only 후처리 채택

Flatline 강제 이상 처리, Gap Filling, Speckle Removal을 각각 비교한 결과, Speckle-only 방식이 가장 높은 검증 성능을 보였다. 따라서 최종 후처리는 길이 2–11인 짧은 이상 예측 구간을 제거하되, 수온 1차 변화량이 1.7 이상인 spike가 포함된 구간은 보호하는 방식으로 구성하였다.

### 6. Threshold 안정화 전략 비교

2025년 상반기를 다시 두 구간으로 나누어 threshold 변동을 확인하였다. 일부 관측소·수심층에서 최적 threshold가 크게 달라지는 현상이 나타나, 불안정한 수심층에 관측소 단위 threshold를 적용하는 안정화 전략을 비교하였다. 이 과정에서 기존 Full-H1 threshold 방식과 stability fallback 방식을 별도 후보로 구성하였다.

### 7. Public Leaderboard를 통한 후보 비교

배포 데이터에서 구성한 여러 threshold 전략을 Public leaderboard에서 비교하였다. Stability fallback 방식은 기존 방식보다 높은 Public F1을 기록하였다. 이후 일부 threshold를 하나씩 변경한 제출 파일을 비교하여 각 변경의 영향을 확인한 이력이 있다.

이 과정은 Public 점수를 이용한 threshold 선택으로 해석될 수 있으므로, 최종 재현 파이프라인에서는 해당 점수를 목적함수로 사용하지 않고 배포 데이터 기반으로 파라미터를 산정하도록 구분한다.

### 8. 추가 시간 검증 결과

2025년 하반기를 검증하는 reverse temporal validation에서, I-ORS는 안정화된 threshold 방식이 더 높은 성능을 보였고 S-ORS는 기존 수심층별 threshold 방식이 더 높은 성능을 보였다. 이에 따라 관측소별로 threshold 전략을 달리 적용하는 방식의 시간적 안정성을 확인하였다.

### 9. 최종 파이프라인 및 재현성

최종 예측은 `150개 피처 생성 → XGBoost 이상 확률 예측 → Threshold 적용 → Speckle-only 후처리 → 제출 CSV 생성` 순서로 수행한다. 모델 및 threshold 산정에 사용되는 데이터와 설정을 명시하고, 학습 산출물이 없는 상태에서도 배포 데이터로부터 동일한 절차를 재실행할 수 있도록 구성한다.

※ 최종 threshold 재산정 및 전체 데이터 재학습은 실제 완료한 경우에만 해당 결과와 함께 기록한다.
